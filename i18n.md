# Reflection for Implementing Internationalization with i18next

## What challenges did you face while setting up i18next?

- One of the main challenges is making sure the i18n.js was properly imported into the index.js, since it threw an error "i18n.changeLanguage is not a function" because when initialized it was not being prompted globally.

## Why is it important to use a library like i18next instead of manually handling translations?

- Manually handling translation would mean to add conditional logic on every inconvenient opportunity which turns to a very chaotic process to maintain.

- 18next made it a more grouped or centralized translations that provides fallbacks that makes switching languages seamless. It also not limited to just one language, you can just add how many languages you need provided they are equivocal to the original used language.

## How would you handle dynamic content (e.g., user-generated text) in a multilingual app?

- If static UI text is present, it can be translated by i18next in one go, but dynamic content is harder to optimally maintain as it involves bumps and hoops that must be tackled. Which by, for simplicity sake, need Google translate or DeepL or allow the users to provide for their own translation.
